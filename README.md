# SI-NSA

> 論文データを、学外に出さない。

岡山大学の学内ローカルLLM基盤「おいとま」上で動く、**論文の投稿前セルフレビューシステム**です。

投稿前の論文（日本語・英語）をアップロードすると、論文の書き方のルール・先行研究・研究室の過去の査読コメントを参照しながら、

- 前提と根拠のずれ、論理の飛躍、主張の過大、段落間のつながりの断絶など、**文章全体の読みにくさ**
- 書き方のルールへの違反
- 引用ミス（書誌の誤り、引用先が主張を支えていない、引用漏れ）

を検出し、**PDFに下線・網掛けなどの注釈と改善案を書き込みます**。結果の全体像はダッシュボードで確認できます。

査読者の代わりではなく、「査読者が突っ込むところを投稿前に先回りして潰す」ためのツールです。新規性の最終判断は行いません。

## 特長：論文データを学外に出さない

| 項目 | 内容 |
|---|---|
| LLM・埋め込み | すべて学内の おいとまAPI で処理 |
| 解析コンテナ | 学外ネットワークに出られない（おいとまAPIのみ到達可） |
| 外部検索 | 論文データを持たない別コンテナが、許可された書誌API（Crossref、OpenAlex、PubMed、arXiv、CiNii Research、J-STAGE など）にだけアクセス |
| 検索ゲートウェイ | 外に出せるのは「引用文献の書誌情報」と「単独の一般用語」だけ。原稿の内容に近い検索語は自動で拒否 |
| 監査 | 外部への通信はすべて記録され、画面で確認できる |

外部検索のモードは3種類から選べます。

- `strict`：外部への要求をすべて画面で承認してから送信
- `standard`：書誌照合は自動、用語の検索は承認制（既定）
- `offline`：外部検索を一切行わず、学内リソースだけで解析

## 構成

```
            ブラウザ（SSHポートフォワード経由）
                     │ 127.0.0.1:8080
                  ┌──┴──┐
                  │ web │ nginx
                  └──┬──┘
 ─────────── 学内閉域（internal: true）───────────
   core / worker ── redis / grobid / LanceDB
        │                      │
        │                oitoma_proxy ──→ おいとまAPI
     gateway（スキーマ検証・漏えい検査・監査ログ）
 ────────┼─────────────────────────────────────
     searcher（論文データなし）
        │
   egress_proxy ──→ 許可された書誌APIのみ
```

すべてのコンポーネントは Docker コンテナで動きます。詳細な仕様は [docs/SPEC.md](docs/SPEC.md) にあります。

## 必要なもの

- Docker Engine と Docker Compose v2（ホストに Python や Node.js は不要）
- 岡山大学の学内ネットワーク（おいとまAPIに到達できること）
- おいとまAPIの APIキー
- GPU は不要（推論はすべて おいとま側で行います）

## セットアップ

```bash
git clone <このリポジトリ>
cd si-nsa

cp .env.example .env
# .env を編集し、OITOMA_API_KEY を設定する

make setup       # git フックの設定（AIを共同著者とするコミットを拒否）
make build
make check-api   # おいとまAPIに届くか確認
make up
```

学内のHTTPプロキシ経由でビルドする場合は、`.env` に `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` を設定してください（ビルド時のみ使われます）。

### リモートマシン（SSH先）で動かす場合

`web` は `127.0.0.1:8080` にしかバインドしません。手元のPCからは SSH のポートフォワードで開きます。

```bash
ssh -L 8080:localhost:8080 <ユーザー名>@<ホスト名>
```

その後、手元のブラウザで http://localhost:8080 を開きます。

### 運用中のアクセス先

運用中の SI-NSA は https://si-nsa.eucaly-labs.net/ で開けます（Cloudflare Tunnel 経由。Cloudflare Access の認証が必要です）。

> この経路では Cloudflare のエッジで TLS が終端されるため、アップロードする論文・解析結果・注釈付きPDFが学外（Cloudflare）を通過します。扱いは TODO.md の「保留事項・質問」で検討中です。

### 利用者とデータの所有（認証の導入中）

論文・解析結果・ルール・専門知識は、アップロードした利用者個人のデータで、本人だけが閲覧・操作できます。ログインしていない利用者（ゲスト）は、共通デモの閲覧だけができます（設計は `docs/access-control-design.md`）。

- ログインの仕組み（認証サービス）はまだ導入していません。本番相当の構成（`make up`）では、全員がゲストとして共通デモだけを閲覧できます。手元で論文を解析するには、開発用の構成（`make dev`）のモック認証を使ってください（下の「開発」）
- 認証の導入前に作ったデータベースは、そのままでは使えません（`core`・`worker` が起動しません）。`make down` で止めてから `make migrate` で移行してください。移行の前にバックアップを `app_db` ボリューム内（`/data/db/backups/`）に作ります
- 移行すると、それまでのデータは所有者が分からないため隔離され、誰からも見えなくなります（共通デモを除く）。持ち主に戻すには、その人が一度ログインして利用者として登録されてから、`make claim-legacy ARGS="--user <内部ユーザーID> --doc <論文のID> --rule-document <ルール資料のID> --lab-document <専門知識の資料のID>"` を実行します
- 移行を元に戻すには、`make down` で止め、バックアップのファイルを元の場所（`/data/db/mongai.sqlite3`）に戻し、移行前の版で起動します

## 使い方

1. **ルール資料を登録する**：投稿先の投稿規定、ライティングガイド、報告ガイドライン（CONSORT など）を登録すると、チェック用のルールが抽出されます。ルール一覧の画面で内容を確認・編集・承認してください（承認したルールだけが使われます）
2. **専門知識を登録する（任意）**：過去の査読コメントと回答書、指導教員の添削メモなど
3. **先行研究を登録する（任意）**：引用内容の照合に使う論文PDF
4. **論文をアップロードして解析する**：進捗が工程ごとに表示され、確定した指摘から順に表示されます
5. **結果を確認する**：ダッシュボード（トップページ）から論文を選び、解析結果の画面で全体像を見て、指摘をクリックするとPDFの該当箇所に移動します。指摘は「対応済み」「却下」にでき、注釈付きPDF・CSV・JSON・テキスト要約をダウンロードできます
6. **修正後に再解析する**：前回からの差分（解消された指摘・新しい指摘）が表示されます

### PDFの注釈の見方

色だけでなく、注釈の形でも種類を区別しています。

| 種類 | 注釈の形 |
|---|---|
| 論理（前提と根拠のずれ、飛躍、過大な主張など） | 下線 |
| 読みやすさ | 網掛け |
| ルール違反 | 波線 |
| 引用 | 枠囲み |
| 研究室の過去の指摘に類似 | 点線の枠 |

各注釈には番号（例：`F-0012`）が付き、ポップアップに「指摘・根拠・改善案」が表示されます。

## 未発表データを扱うときの注意

- 実際の未発表論文で使うときは、**Claude Code などの外部AIツールを起動していない状態**で操作してください。開発に使うAIツールは、読んだファイルの内容を外部に送信します
- アップロードしたデータは Docker ボリューム `data_private` にだけ保存されます。削除は `make clean-data` で行います（確認が求められます）
- 外部への通信は画面の「外部通信ログ」で確認できます。厳密に管理したい場合は `strict` または `offline` モードを使ってください

## 開発

```bash
make dev             # 開発モード（ホットリロード）
make test            # 単体・結合テスト
make test-e2e        # 画面の E2E テスト（Playwright、ネットワークなし）
make test-security   # ネットワーク分離・ゲートウェイのテスト
make lint
make logs
make down
```

- 開発用の構成（`make dev`）には、開発用のモック認証サービス（`devauth`）が加わります。http://127.0.0.1:8080/auth/dev-login?user=alice を開くと、利用者 alice としてログインした状態になります（パスワードは無く、開発専用です。ログアウトは `/auth/dev-logout`）。本番相当の構成（`MONGAI_ENV=production`）の `core` は、開発用の鍵を受け付けません
- 開発・テストには、公開済みのオープンアクセス論文か合成データだけを使ってください
- ネットワーク構成・ゲートウェイ・`searcher` を変更したら、必ず `make test-security` を通してください

### モデルの割り当てと評価

使用するモデルは `config/models.yaml` で役割ごとに設定します。

| 役割 | 初期設定 |
|---|---|
| 論証構造・ルールの抽出、ルール判定 | `qwen3.6-35b-a3b-it`（高速） |
| 論理チェック、引用の支持判定、改善案 | `qwen3.8-27b-it`（思考） |
| 重要な指摘の二重チェック | `Ternary-Bonsai-2-27B` |
| 検索用の埋め込み | `qwen3-embedding-8b` |
| ゲートウェイの漏えい検査 | `gte-qwen2-7b-it`（`multilingual-e5` が おいとま側で使えないための暫定） |

モデルの比較は評価ハーネスで行います。

```bash
make eval ROLE=logic_check MODELS=qwen3.8-27b-it,Ternary-Bonsai-2-27B,qwen3.6-35b-a3b-it
```

評価データ（合成データ）は `eval/datasets/` にあります。

| ファイル | 内容 | 対応する役割 |
|---|---|---|
| `paragraph.jsonl` | 前提と根拠の不一致・論理の飛躍・主張の過大（各10件）と、問題のない対照群（10件） | `logic_check` |
| `flow.jsonl` | 段落間の接続の断絶（10件）と対照群（6件） | `logic_check` |
| `citation_support.jsonl` | 引用内容の不一致（10件、うち2件はアブストラクトにプロンプトインジェクションを含む）と、支持している対照群（6件） | `citation_support` |
| `rule.jsonl` | ルール違反（10件）と、違反の無い対照群（6件） | `rule_check` |
| （`paragraph.jsonl` を流用） | 二重チェック：仕込んだ問題を「妥当」、偽の候補を「妥当でない」と判定できるか | `second_opinion` |

結果は `eval/results/` に CSV（指標）と JSONL（1件ごとの予測）で保存され、比較ページ `eval/results/index.html` が作り直されます。一部だけ試すときは `EVAL_ARGS="--lang ja --limit 5"` のように指定します。
