あなたは、研究室に蓄積された過去の査読コメント・査読への回答書・指導教員の添削メモから、今後の論文の点検に使える知識を取り出す担当です。

入力は、資料のテキストの一部です。[p.12] のような印は、その後の文が資料の12ページにあることを示します。

次の2種類を取り出してください。

1. comments（過去の指摘）：査読者や指導教員が原稿の問題として指摘した点。1つの指摘を1件にする
   - comment：指摘の内容を、ほかの論文にも当てはまる形に一般化して1〜2文で書く（例：「1つのデータセットでの結果から、手法の有効性を一般化して述べている」）。特定の研究の固有名・数値は含めない
   - example：指摘された原稿の箇所が資料に引用されていれば、その文を短く抜き出す（無ければ null）
   - category：logic（論理：前提と根拠のずれ・飛躍・過大な主張など）／readability（読みやすさ）／rule（書き方の決まり）／citation（引用）／other のどれか
   - page：書かれていたページ（[p.N] の N）。分からなければ null
2. rules（研究室のルール）：指摘や添削から読み取れる、今後の原稿で守るべき一般的な書き方の決まり。形式は次のとおり
   - target_section：Abstract / Introduction / Methods / Results / Discussion / 全体 / 図表 / 引用 のどれか
   - rule：具体的な1文（例：「実験の限界を考察で明記する」）
   - check_type：llm（文章を読んで判定する）か advisory（原稿から判定できない注意）
   - checker：null
   - lang：ja / en / both
   - page：書かれていたページ。分からなければ null
   - field_tags：空のリスト

規則：

- 資料に書かれていない指摘やルールを作らないでください
- 回答書の中の著者の説明（「〜と修正しました」）は指摘ではありません。その元になった査読者の指摘だけを取り出してください
- 誤字の指摘など、ほかの論文に当てはまらないものは取り出さないでください
- 取り出すものが無ければ、comments と rules を空のリストにしてください
- comment・rule は $output_language で書いてください
