# 文字の設計（タイポグラフィ）

SI-NSA のフロントエンドの文字（書体・大きさ・太さ・行間・字間・数字の表示）の設計と、その根拠をまとめる。
定義の実体は `frontend/src/theme/typography.css`（唯一の定義元）で、この文書はその説明である。値を変えるときは両方を直す。

最も重視するのは装飾ではなく、**情報を正確に、楽に読み取り、操作できること**である。

## 1. 採用した書体と理由

| 書体 | 役割 | 読み込む太さ | 採用した理由 |
|---|---|---|---|
| **BIZ UDPGothic** | 本文・操作（メニュー・ボタン・フォーム・表・通知・エラー） | 400 / 700 | モリサワのユニバーサルデザイン書体。字形の判別しやすさに配慮されていて、長い日本語の文章も読みやすい。かなが詰め組み用の幅（P＝プロポーショナル）で、説明文や表の文字が間延びしない |
| **Zen Kaku Gothic New** | 見出し（画面の題名・欄の見出し） | 700 | 本文と字形を変え、色や大きさだけに頼らずに階層を示す。落ち着いた現代的なゴシックで、日本語の見出しとして自然 |
| **IBM Plex Sans** | 数値・日時・所要時間・ID・モデル名 | 400 / 600 / 700（英数字だけ） | 数字の判読性が高く、**0〜9 がすべて同じ幅**（600/1000em）なので、表や1秒ごとに変わる所要時間で桁が揃い、横に揺れない |
| Noto Sans JP | 補完だけ | 400 / 700 | BIZ UDPGothic に無い漢字（約5,000字。論文の題名に出る稀な字など）を補う。本文の第一書体としては使わない |

いずれも Google Fonts で公開されているオープンソースの書体で、ライセンスは **SIL Open Font License 1.1**。

### 選定のときに確かめたこと（2026-10-16、@fontsource の各パッケージの WOFF2 を fontTools で調べた）

- **BIZ UDPGothic の数字は「1」だけ幅が狭い**（1290 / ほかは 1556、単位は 2048em）。等幅の数字にする OpenType の機能（`tnum`）も無いため、`font-variant-numeric: tabular-nums` を指定しても桁は揃わない。→ 桁を揃えたい値は IBM Plex Sans で表示する
- IBM Plex Sans の数字は既定で等幅。`tabular-nums` は念のため指定している（ほかの書体に替えても意図が残るように）
- 収録字数：BIZ UDPGothic 11,606 字、Zen Kaku Gothic New 7,705 字、Noto Sans JP 16,657 字。JIS 第1・第2水準は BIZ UDPGothic と Noto Sans JP で同じだけ収録（どちらも 49 字が未収録で、同じ字）
- Zen Kaku Gothic New には全角のチルダ「～」（U+FF5E）と水平線「―」（U+2015）が無い。見出しにこれらが出たときは、次の BIZ UDPGothic で表示される
- Zen Kaku Gothic New には詰め組みの機能（`palt`）が無く、見出しはベタ組み（文字を全角の幅で並べる）になる。カタカナの「ン」「リ」など字面が小さい字の前後は、少し空いて見える
- 混植（日本語と数字の組み合わせ）は役割の単位で行う。日本語の文の途中の数字（「指摘の一覧（重大度の順、14件）」など）は本文の書体のままにし、文の中で書体を切り替えない

## 2. 書体ごとの役割（どの文字にどの書体を使うか）

| 文字 | 書体 | 指定のしかた |
|---|---|---|
| 本文・説明・通知・エラー・メニュー・ボタン・入力欄・ラベル・表の文字・バッジ・ログインの状態・メールアドレス | BIZ UDPGothic | `body` の既定（`--font-family-body`）。フォーム部品も本文の書体を継ぐ |
| 画面の題名（`h1`）、欄の見出し（`h2`・`.panel-title`）、小見出し（`h3`） | Zen Kaku Gothic New | `typography.css` の要素の既定 |
| 総指摘数などの全体指標（`.kpi-value`）、重大度別などの件数（`.kpi-breakdown dd`）、表の数値の列（`td.num`）、所要時間（`.elapsed`） | IBM Plex Sans | `typography.css` で、これらのクラスに数値の書体を当てている |
| 日時（解析日時・開始日時・外部通信ログの日時）、指摘の番号（F-0001）、使用モデル、API のリクエスト数・トークン数、PDF のページ番号・拡大率 | IBM Plex Sans | 要素に `className="numeric"` を付ける |
| グラフの項目名・単位 | BIZ UDPGothic | `BarChart.tsx` が `typography.css` の変数を読んで ECharts に渡す |
| グラフの目盛り・値 | IBM Plex Sans | 同上 |

ヘッダーのロゴは SVG 画像で、書体の変更の対象外（造形は変えていない）。

## 3. 大きさと太さのスケール

大きさは `rem` で書く（1rem は、ブラウザの既定の文字の大きさ。既定のままなら 16px）。ブラウザの文字サイズの設定と拡大に従う。

| 変数 | 用途 | PC | スマートフォン（幅 40em＝640px 以下） |
|---|---|---|---|
| `--font-size-display` | ゲストのトップの題目 | 28px | 22px |
| `--font-size-page-title` | 画面の題名（h1） | 26px | 22px |
| `--font-size-subtitle` | 指摘の詳細の題名・重大度別などの件数 | 20px | 18px |
| `--font-size-section` | 欄の見出し（h2） | 18px | 18px |
| `--font-size-lead` | トップの主な操作のボタン | 17px | 17px |
| `--font-size-body` | 本文 | 16px | 16px |
| `--font-size-input` | 入力欄の文字 | 16px | 16px |
| `--font-size-nav` | ヘッダーのメニュー | 15px | 16px |
| `--font-size-button` | ボタン | 15px | 16px |
| `--font-size-label` | 入力欄のラベル | 15px | 15px |
| `--font-size-help` | 入力欄の説明 | 15px | 15px |
| `--font-size-table` | 表の本文 | 15px | 15px |
| `--font-size-caption` | 補助情報（注記・表の列名・メタ情報・バッジ・グラフの文字） | 14px | 14px |
| `--font-size-kpi` | 全体指標（総指摘数など） | 48px | 40px |
| `--font-size-kpi-unit` | 全体指標の単位（件） | 20px | 20px |

- **14px より小さい文字は使わない**（以前は 12〜13px の文字があったが、すべて 14px 以上にした）。単体テスト（`typography.test.ts`）で確かめている
- メニュー（1120px 以下の開閉式）とスマートフォンのボタン・入力欄は 16px（押しやすさと、iOS Safari が入力時に画面を拡大しないため）
- 太さは、読み込んでいる太さだけを使う：本文・見出しは 400 と 700、数値の強調は 600（`--font-weight-numeric-strong`）。太字は見出し・選択中のメニュー・重大度の高い指摘・エラーなどに限る

## 4. 行間・字間

| 変数 | 値 | 用途 |
|---|---|---|
| `--line-height-body` | 1.7 | 本文 |
| `--line-height-dense` | 1.55 | 表・注記・説明など、短い文が続くところ |
| `--line-height-ui` | 1.45 | ボタン・入力欄・メニュー・ラベル |
| `--line-height-heading` | 1.35 | 見出し・件数 |
| `--line-height-numeric` | 1.15 | 大きな数値（全体指標） |

- ボタン・メニューは行間を詰めた分だけ上下の余白を広げ、以前と同じ高さ（押せる範囲）を保った
- 字間は本文 0.02em、見出し 0.01em、数値 0。日本語の字間は広げすぎない。数値は 0 にして桁を揃える

## 5. 日本語と英数字の組み合わせ

- 本文の書体（BIZ UDPGothic）は英数字も読みやすく作られているので、英語の論文の題名、メールアドレス、文中の数字は本文の書体のままにする
- 数値の書体（IBM Plex Sans）は、数値・日時・ID など **英数字が主の値の要素だけ** に当てる。その中の日本語（「件」「回」「前回比」など）は、並びの次の BIZ UDPGothic で表示される
- 見出しの中の数字・英字は見出しの書体（Zen Kaku Gothic New）のまま

## 6. 数値の表示

- 桁を比べる値（表の数値の列、件数、日時、所要時間）は `.numeric`（または数値の役割の既存クラス）で IBM Plex Sans と `font-variant-numeric: tabular-nums` を当てる
- 表の数値の列は右に揃える（`.data-table .num`）
- 数値には単位を付ける（「14件」「67回」）。グラフの値の単位も同じ
- 3桁ごとの区切りは `toLocaleString("ja-JP")`

## 7. レスポンシブ

- 画面の幅の区切りは `em` で書く（40em＝640px、60em＝960px、70em＝1120px、85em＝1360px。既定の文字の大きさのとき）。ブラウザの文字サイズを大きくした利用者では、早めに狭い画面の配置（開閉式のメニュー、1列の配置）になり、文字が大きくてもはみ出さない
- スマートフォンで変えるのは、画面の題名・全体指標を小さくすること、指で操作する部品（メニュー・ボタン）を 16px にすることだけ。本文・表・補助情報の大きさは変えない
- 縦棒グラフの項目名は1本分の幅の中で折り返し、「2 関連研究」のような項目名は番号と名前の間で改行する。1本に要る幅（4.5rem）が取れない幅では横棒にする
- E2E テスト（`e2e/typography.spec.ts`）で、ブラウザの既定の文字の大きさを 24px（150%）・32px（200%）にしても、主な画面が横にはみ出さないことを確かめている

## 8. 書体の配信（セルフホスト）

**実行時に Google Fonts（fonts.googleapis.com・fonts.gstatic.com）には一切通信しない**（CLAUDE.md 最優先ルール5）。

- npm の `@fontsource/*`（版を固定）を `frontend/src/main.tsx` で読み込み、Vite がビルド成果物（`dist/assets/`）に書体のファイルを含める。nginx が同じオリジンから配信し、CSP の `font-src 'self'` は変えていない
- 日本語の書体は、Google Fonts と同じく文字の範囲（`unicode-range`）ごとに約120のファイルに分かれている。ブラウザは画面で使う字のファイルだけを取得する
- IBM Plex Sans は英数字（`latin-*.css`）だけを読み込む
- `vite.config.ts` の設定：
  - `woff2Only`：@fontsource の CSS から WOFF の指定を除き、WOFF2 だけを配信物に含める（使われない WOFF が同じ数だけ増えるのを防ぐ）
  - `assetsInlineLimit`：小さな書体のファイルも `data:` URI にしない（CSP の `font-src 'self'` は `data:` を許さない）
  - `copyFontLicenses`：書体のライセンスの写しを `dist/licenses/fonts/` に含める
- `font-display` は @fontsource の既定の `swap`（読み込むまでは代わりの書体で表示し、読み込んだら差し替える。文字が見えない時間を作らない）
- **プリロードはしない**。日本語の書体はどのファイルが要るかが画面の文字で決まり、事前に絞れない。英数字の書体（約14KB）は小さく、プリロードしても効果が小さい
- Service Worker（`public/sw.js`）は `/assets/` 以下をキャッシュ優先で保存する。書体は一度表示した字の分が端末に残り、閉域・オフラインでも同じ書体で表示される。書体を入れ替えたので、キャッシュの名前を `mongai-shell-v4` に上げた（古い書体のファイルは消える）

### 容量（2026-10-16 の計測。キャッシュが空の状態で、画面を最初に開いたときに取得する書体の量）

| 画面 | 変更前（Noto Sans JP のみ） | 変更後 |
|---|---|---|
| トップ（ログイン中、1440px） | 44 ファイル・475KB | 51 ファイル・704KB（BIZ 592・Zen 68・Plex 44） |
| 解析結果（1440px） | 53 ファイル・568KB | 69 ファイル・910KB（BIZ 683・Zen 146・Plex 68・Noto 13） |
| 指摘の詳細（1440px） | 47 ファイル・507KB | 53 ファイル・711KB |
| ルール（390px） | 33 ファイル・374KB | 40 ファイル・527KB |

書体を3つに分けたため、最初の表示で取得する量は4〜6割ほど増える。2回目以降はブラウザと Service Worker のキャッシュから読む。
配信物（`dist/`）全体は、WOFF を除いたため 20.1MB から 21MB への増加にとどまる。

## 9. フォールバック

- どの並びも「自前で配信する書体 → 総称の `sans-serif`」で、OS の書体名は書かない（OS ごとの差を減らす）
  - 本文：`"BIZ UDPGothic", "Noto Sans JP", sans-serif`
  - 見出し：`"Zen Kaku Gothic New", "BIZ UDPGothic", "Noto Sans JP", sans-serif`
  - 数値：`"IBM Plex Sans", "BIZ UDPGothic", "Noto Sans JP", sans-serif`
- 字が無いときは並びの次の書体で表示する。Noto Sans JP のファイルは、その字が出たときだけ取得される
- `sans-serif` が使われるのは、書体の読み込み中（`swap`）と、読み込みに失敗したときだけ
- ネイティブの選択肢の一覧（`select` を開いたときのメニュー）や、ファイル選択の「ファイルが選択されていません」などの文言は OS・ブラウザが描くので、書体は完全には揃わない（カスタムの部品には置き換えない）

## 10. グラフ（ECharts の Canvas）

- Canvas に描く文字は CSS の書体の指定を継がない。`theme/typography.ts` の `readChartTypography()` が `typography.css` の変数を読み、ECharts の `textStyle`・軸・値のラベルに渡す（値を書き写さない）
- 書体の読み込み前に描くと、代わりの書体で描かれたうえに、ECharts（zrender）が測った文字の幅が書体名ごとに残る。そのため、`whenFontsLoaded()` で **描く字の分の書体の読み込みを待ってから最初に描く**。読み込み済みならすぐ描く。失敗しても、3秒たっても描く（描画を止めない）
- 待つ間はグラフの高さを確保しているので、配置はずれない。画面を離れたら待つのをやめ、イベントの監視（ResizeObserver）も外す
- E2E テストで、グラフの Canvas ができた時点で書体が読み込み済みであることを確かめている

## 11. 新しい画面・部品を作るときのルール

1. 文字の値（`font-size`・`font-weight`・`line-height`・`font-family`）を直書きしない。`typography.css` の変数を使う（`global.css` に直書きがあると単体テストが失敗する）
2. 見出しは `h1`〜`h3` か `.panel-title` を使えば、見出しの書体・太さ・行間になる。見た目を見出しにしたくない `h2`（`.home-usage-title` など）は、本文の書体に戻す
3. 数値・日時・ID・モデル名など英数字が主の値は `className="numeric"`。日本語の文の中の数字には付けない
4. 補助情報は `.note`・`.sub`（14px）。これより小さくしない。小さくする必要があるときは、理由をこの文書に書く
5. 新しい大きさが要るときは、まず既存の変数で足りないかを考え、足りなければ `typography.css` に役割の名前で変数を足し、この文書の表にも書く
6. 書体・太さを増やすときは、`main.tsx` の読み込みと、この文書・`docs/dependencies.md` を直す。使わない太さは読み込まない
7. グラフなど Canvas に文字を描くときは `readChartTypography()` と `whenFontsLoaded()` を使う
8. 色だけで階層を表さない（大きさ・太さ・書体でも区別する）

## 12. 確認の方法

- `make test`：`frontend/src/theme/typography.test.ts`（最小の大きさ・行間の範囲・自前の書体だけの並び・直書きの禁止・読み込み待ち）と、`tests/unit/test_compose_structure.py` の CSP の `font-src 'self'` の検査
- `make test-e2e`：`frontend/e2e/typography.spec.ts`（役割ごとの書体、書体がすべて同じオリジンから WOFF2 で取得され 404 も外部への通信も無いこと、本番と同じ CSP で違反が無いこと、グラフが書体の読み込み後に描かれること、文字サイズ 150%・200% で横にはみ出さないこと）
